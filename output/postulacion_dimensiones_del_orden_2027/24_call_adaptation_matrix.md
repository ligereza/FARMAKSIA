# Call adaptation matrix

This document separates one artistic core from different funding wrappers. It prevents the same technical idea from being submitted as if it were simultaneously an audiovisual work, a research study, a workshop and a diffusion project.

## Artistic core

`Dimensiones del Orden` is a live audiovisual work in which screens and LED surfaces operate as luminous architecture. They do not primarily display a movie or illustrate an external narrative. They receive a shared state of phase, tempo, energy, density, direction, topology, palette and transition, and transform that state into luminance, color, movement and spatial relations.

The physical luminaires and the screen surfaces are therefore two material interpretations of the same light score. Blender and Geometry Nodes provide the procedural reference; TouchDesigner and the available control protocols provide the live execution; the layout of the venue determines how the light score propagates. Audio is a temporal input to the state, not a decorative soundtrack or a simple beat trigger.

The artistic question is whether a mathematical relation can remain legible when it crosses simulation, LED surfaces and heterogeneous lighting systems, and whether the differences introduced by mapping, patch, latency, resolution and device capability can become visible material of the work.

## Adaptation A - audiovisual experimental production

This is the canonical version already developed in this dossier. The work must be stated as an audiovisual result, not as a software product. The software is the generative and translation instrument that makes the work possible.

The central sequence is:

`procedural reference -> semantic light state -> layout and capability verification -> LED and luminaire interpretation -> live work -> process document`

The three phases remain preshow, soundcheck and liveshow. Preshow observes the physical arrangement and creates a spatial profile. Soundcheck verifies identity, patch, timing and capability. Liveshow freezes the verified layout and exposes any translation loss instead of hiding it.

The application should promise one controlled configuration, a bounded number of luminaires and a finished live work. It should not promise a universal autopatcher, complete compatibility with every console or a finished commercial platform.

## Adaptation B - regional creation and new formats

This route should not copy the audiovisual application. It should present the same core as a site-specific luminous installation or a new-format artistic system installed in a real regional venue.

The decisive change is the role of place. In the audiovisual call, the venue supports the work. In regional creation, the venue becomes a co-authoring variable: its dimensions, walls, distances, power, audience path and available light determine the graph from which the composition is generated.

The regional version must therefore add:

- a concrete venue or a credible venue pathway;
- a public exhibition plan;
- a reason why the regional space changes the work;
- a smaller and financially credible hardware configuration;
- documentation of how the public encounters the light field.

The mapping system remains an artistic instrument. The proposal should say that it reconstructs the venue so the work can respond to its actual geometry, not that it sells automatic installation services.

## Adaptation C - diffusion

Diffusion is downstream of creation. It can fund the public circulation of the finished work through an exhibition, a live presentation, a virtual tour or another public format, but it should not be used to finance the first construction of the common control layer.

If this route is used later, the core package becomes an existing work, a public-access plan, a venue or platform, an audience strategy and accessible documentation. The technical annex becomes evidence of the work's format and portability, not the principal research question.

## Adaptation D - formative activity

The formative version would be a free laboratory called, for example, `Luz entre sistemas`: participants build a small spatial graph, generate a procedural state, map a few light sources or LED surfaces, compare native and semantic control and document the resulting translation loss.

The learning outcome is not mastery of a specific console. It is the ability to express a light intention as relations of phase, tempo, energy, density and distance, then inspect how a concrete device interprets or limits it. The activity must include a real transfer plan and a participant profile; it cannot be a disguised request for production funds.

## Adaptation E - research

The research line is appropriate only if the question changes from “can I produce this work?” to “how do Chilean artists, technicians and venues negotiate the relation between screens, light, protocols, interfaces and spatial installation?”

That project would need a field sample, interviews or observations, an analysis method, a public report and a knowledge-transfer activity. The current procedural scene and live prototype could serve as a research instrument or case study, but they cannot substitute for fieldwork.

## Ecosystem boundaries

The private ecosystem is useful as a development lineage but should not be listed as a bundle of funded deliverables in the primary application:

- `MOSAIK` is the domain-specific live-show and Resolume knowledge base.
- `XIO` is the signal and transport layer for OSC, Art-Net, timecode and networked devices; in this work it is an instrument for capture, verification and transport, not the artistic result.
- `LUCIDA` is the surface and connector architecture for reversible overlays and previews; it can later expose the common state to different applications.
- `VIZZ` concerns human visual signals and adaptive interfaces; it is outside the current light-work scope.
- `PUPILA` concerns analogy and interface learning; it is a future educational or operational layer, not a deliverable of this application.
- `IRIS` concerns evidence, archive and portfolio relations; it can document the process but should not replace the audiovisual work.

The transferable asset is the contract between a semantic state, a spatial layout, device capabilities, timing evidence and a reversible projection. Each project keeps its own grammar and consumer.

## Self-critique and correction

The strongest current risk is that the proposal could be read as an interoperability product rather than an artwork. The correction is to place the luminous experience first and describe the software as the mechanism that makes the artistic question observable.

The second risk is scope inflation. Blender, TouchDesigner, LED, DMX, Art-Net, OSC, RDM, camera mapping, audio and several consoles cannot all be promised as equally mature. The funded slice must choose one reference backend, one live backend, one controlled physical layout and one bounded comparison. Other protocols remain future transfer targets.

The third risk is overclaiming camera automation. A camera can assist layout reconstruction, while RDM can assist device discovery when fixtures support it. Neither guarantees a complete patch in every venue. The application therefore promises proposals, verification and visible uncertainty, not silent automation.

The fourth risk is that screens are treated as a generic visual backdrop. The work avoids this by making LED luminance part of the same semantic state as the physical beams. Screen resolution, pixel density, refresh, color response and latency become measurable translations of the light score.

The fifth risk is insufficient public result. A technically elegant adapter is not enough. The closing package must contain a live audiovisual work, an intelligible audiovisual record, a process document and a reproducible parameter archive.

## Decision

Submit the current project first to `Produccion de obras experimentales - Fondo Audiovisual 2027`, because its required result exactly matches the work plus process document already prepared. Prepare a regional creation variant only if a real venue and exhibition plan can be confirmed. Keep diffusion, formative and research as separate future wrappers with their own evidence and objectives. Do not submit one technical core five times with superficial changes.
