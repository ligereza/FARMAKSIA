## Regla de comunicación

No mostrar al usuario rutas internas, alias, cachés ni resolución de skills. No usar frases como “la ruta abreviada del skill no coincide” o equivalentes. Las skills se leen internamente; el progreso debe comunicar sólo cambios del repositorio, evidencia, errores reproducibles y próximos pasos.

## Regla de idioma técnico

El idioma del usuario no determina el idioma del código. Todo código y contrato técnico debe usar inglés ASCII estricto: identificadores, nombres de archivos y carpetas, imports, ramas técnicas, claves de eventos, fixtures, tests, logs parseables y nombres de recursos. No usar tildes, `ñ`, umlauts ni otros caracteres no ASCII en esos elementos. La interfaz, documentación explicativa y textos dirigidos al usuario pueden estar en cualquier idioma, pero deben mantenerse separados de los identificadores y contratos técnicos. Cada agente debe verificar esta regla offline antes de entregar cambios.
